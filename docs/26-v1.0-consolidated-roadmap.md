## 3. The ordered plan

**Ordering rationale.** (1) Finish cheap loose ends first (derisk, complete the map story) **and the
APRSCaching fidelity cluster O6** (it restores the original concept's character and several pieces —
F-5 decoders — seed the Tools system). (2) Build the **packet stack (P1–P4)** with the **GP hardware +
terminal-UX adoptions (O7/O8)** folded in — the largest remaining capability and the foundation both
the retro shell and the Tools system need. (3) Build the **Tools plugin system (O9)** once the terminal
exists (its first extension surface). (4) Ship the **two themes + the flip (O3)** as a *single* merged
stage — the Cogmind theme tokens **and** the retro terminal shell land together, because switching to
Cogmind *is* the late-90s flip; only do it once the component set (incl. packet + Tools surfaces) is
stable, since a theme re-skins finished surfaces. (5) **Release prep last**, so screenshots/marketing
reflect the final, themed product. CI is explicitly post-1.0.

**Theme decision (supersedes `docs/24` light-mode scope):** v1 ships **exactly two themes, both
DARK-ONLY — Modern** (the current default visual language) and **Cogmind** (the late-90s green-screen
flip). There is no light mode. Switching theme to Cogmind performs the retro shell transformation in
one motion; there is no separate "retro shell" stage decoupled from the theme.

### Stage 2 — The "Tools" plugin/scripting system (`docs/27` Part B.3)
*Closes O9. Depends on Stage 1 (the terminal/BBS are its first extension surfaces).*
- Build **"Tools" — sandboxed, capability-gated plugins** (Lua via `wasmoon`/Fengari *or* a locked-down
  JS worker; both MIT, no ambient network/DOM/FS). A Tool is a **signed manifest + script** (`tool.json`:
  name, author callsign, permissions, entry).
- **Host API (extension points):** register a `/command` in the terminal/BBS; hook events
  (`on_frame`/`on_connect`/`on_disconnect`/`on_beacon`/`on_find`/`on_spot`); contribute monitor
  filters/colourisers; provide decoders; schedule beacons; add a small theme-aware panel/overlay or
  declarative map layer. Versioned, a11y + reduced-motion inherited.
- **Built-in set (ships curated):** the **F-5 PSK31 + CW (Morse) decoders** (Web Audio, reusing the H4
  pipeline — this is where O6's F-5 lands), an **auto-responder** (GP PMS-style), a **CTEXT macro pack**,
  a **monitor colouriser** (drives off the `NAMES.GP` registry), a **beacon scheduler**.
- **Guardrails:** capability grants are explicit; anything that **transmits** still passes the existing
  **H5 / control-verification** TX gates; a Tool can **never** bypass `verify.ts` trust. CPU/time
  budgeted; off by default, opt-in per Tool. (Heritage: GP's parser-DLLs + GPRI `//PW` scripting.)
- **DoD:** the built-in decoders + auto-responder run sandboxed; import-by-URL prompts for permissions;
  no Tool can transmit without the TX gate; tri-runtime green; warrants its own impl doc when scheduled.

## 5. Definition of "feature-complete for v1.0.0"

Every doc's **in-scope** deferred item is built (§2 top table): the map story closed + the APRSCaching
fidelity cluster restored (Stage 0 / O6); the packet world live with the GP hardware + terminal-UX
adoptions (Stage 1 / O2+O7+O8); the Tools plugin platform shipped with its built-in decoders (Stage 2 /
O9); the app on **two dark-only themes** where selecting Cogmind *is* the late-90s flip (Stage 3 / O3);

"deferred/reserved" list is **knowingly excluded** — those are reserved seams or owner-deferred (CI),
not gaps.
At `v1.0.0` the trust model is **Tier B (app-geo) + honest Tier C**, with Tier A designed-for and
RF-deferred (`docs/22`) — a conscious, documented choice, not an omission.

## 6. Risks & sequencing notes

- **Packet (Stage 1) is the long pole** and the highest-risk RF code. P0's pure, tested core de-risks
  it; keep every new layer (P2–P4) pure-core + scripted tests, with hardware as validate-at-deploy.
- **Theme + flip last, after packet *and* Tools.** The flip is now a single merged stage (theme tokens
  + retro shell together); re-skinning a moving target is waste, so freeze the component set (Stages
  1+2) before Stage 3.
- **Two dark themes only — no light mode.** This supersedes `docs/24`'s light-mode scope; don't build a
  light variant for v1.
